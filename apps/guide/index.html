Trust, tested.

MindBot is an agent system built to make its work inspectable: independent records, a second-model critique loop, and expensive reasoning reserved for decisions that change the outcome.

01 / The problem

A log is a claim—not proof.

MindBot may say, “I checked three sources and found no conflict.” But that sentence was generated by the same system that performed the work. It can omit a failed tool call, misremember a result, or produce a convincing account of work it never completed. A self-written log helps with debugging; it cannot independently verify behavior.

03 / Quality control

A second set of eyes.

MindBot does not accept its first answer as final. A builder model drafts a response; a separate critic model checks it against a rubric: correctness, evidence, safety, and completeness. The builder revises only when the critique identifies a concrete gap. This makes mistakes visible before they reach you.

Draft → Critique → Revision

Edit the draft, then move through the loop.

Critic rubric
STATE: Draft
CRITIC
Circular evidence: the log is self-authored. The answer needs independently verified evidence.
REVISION
Replace log-based proof with evidence captured independently by tools, gateways, or an externally anchored provenance record.

A critic improves quality—but only the rubric and evidence it can inspect.

04 / Efficiency

Spend intelligence where it changes the outcome.

MindBot uses a costly, capable model to plan, judge, and handle ambiguity. Cheaper workers search, extract, format, and run repeatable steps. The expensive model is the foreperson, not every construction worker.
